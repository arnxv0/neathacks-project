## 2026-10-11 — Xcode update broke `make`; fixers' first attempts failed tests for an environmental reason

Xcode updated overnight and `/usr/bin/make` refused to run until `sudo xcodebuild -license accept` (no sudo available to the agent; Homebrew also refused). The target's `test_command` is `make test`, so the first fixer attempt of the first three clusters in `20261011-001111-d070` (a5-schema, a6-watchlist, b2-b3-retry) came back `tests_green=false` and burned a retry each (~$1.0–1.6 of Claude Code per attempt). Workaround: `~/.local/bin/make -> /Library/Developer/CommandLineTools/usr/bin/make` (GNU Make 3.81, runs without the license shim); `~/.local/bin` is first on PATH so the live coordinator picked it up with no restart. Preflight behaved correctly: it refused to treat an untested fix as done and handed the exact failure text to the retry. Follow-up: the dispatcher could recognise an environment failure of `test_command` (command not found / license prompt) and raise an `env.failed` recovery instead of spending a retry.

## 2026-10-11 — Full-mode run `20261011-001111-d070`: wall clock, resume, merge conflicts

- **Wall clock.** `guard.assessment_timeout_s` (1500 s) is per coordinator *process*. The attack+grade phase took ~12 min; the fix phase for 15 clusters (3 fixers in parallel, 3–12 min each) could not fit the remainder. The cap was **not raised**. The first process kept producing fix commits on their branches (replays raised `Stopped` at the cap, which the ledger records), then `preflight resume` ran in a fresh window and replayed every branch (15/15 reached K/K: 205 replay runs). Resume is the designed path for this; the cap stays as the runaway brake.
- **Fix branches were rebased on main before resume** (`git rebase main` in each worktree) because main had gained the `python -m app` entry point the replay boot command now needs. Same fix commits, new SHAs; `Entire-Checkpoint` trailers survive where present.
- **Merge conflicts were common and are a feature, not a bug.** 11 of 15 approved branches conflicted on `prompts/system.md` or `app/retry.py` because several fixers hardened the same prompt/tool paths. `approve` handles this: abort the merge, replay the cluster against *current main*, and if main already passes K/K record the cluster as closed-by-main (9 clusters, e.g. A6's role gating also closed G1/G2/G3, B1–B3's retry fix also closed B2/B3). Two clusters (C3, E1) still failed on main → `needs_human` → `request-changes` with a reviewer comment telling the fixer to merge main and keep both sides. Regression suite after approvals: 13 suites, 0 regressed.
- **Report gap fixed:** `_maybe_finish` treats `needs_human` as non-blocking, so the first report had after = 2/50 with C3/E1 open; the final approval re-runs regression + after pass. `report.json` now carries `recoveries[]` built from events.

## 2026-10-11 — SQLite ledger store (owner request)

The file ledger is gitignored run output and awkward to share or gate. Added `src/preflight/db.py`: a write-through SQLite mirror of every ledger write (manifest, runs+verdicts+steps, clusters, attempts, events, regressions), WAL mode so the coordinator, replay threads and the approve/regress CLIs can write at once, and read-only access via `preflight db query` and `GET /api/db/query` (single SELECT, read-only connection). The files stay the authoritative write path (transcripts, diffs and briefs are files the dashboard and fixers read); `preflight db sync` rebuilds the store from them, so the store can never be the thing that breaks a run. Access management is now a property of the API in front of one file, not of a directory. Known wrinkle: two processes appending to `events.jsonl` concurrently can reuse a `seq`; the store keys events on (assessment, seq), so 798 file events became 792 rows for the full run.

## 2026-10-11 — Entire checkpoints finally work: the hook deadlocked on a Rosetta git

Every Entire hang this weekend (post-commit hook never returning, stop hook ~10 min, session-start blocking on stale locks, zero checkpoints despite trailers on every fixer commit) had one cause: `git` on this Mac resolved to `/usr/local/bin/git`, the 2021 Intel build (git 2.33) running under Rosetta. Entire's post-commit hook drives `git update-ref --stdin` and the two deadlock. The Apple git behind `/usr/bin/git` was unusable because a fresh Xcode update demanded licence acceptance. Fix: an arm64 git first on PATH (`~/.local/bin/git -> /Library/Developer/CommandLineTools/usr/bin/git`, 2.39) and the stale `.git/entire-*-locks` removed. Smoke test on the target: the hook completed instantly, `entire checkpoint list` shows checkpoint `01M4N44YYFY4BNW5WW07GK0VBH` for commit 4e9d5d5. Entire is now enabled on this repo too, and this entry is itself written and committed by a Claude Code session so the repo carries a real checkpoint. The reaper in `claude_code.py` stays as a safety net.
